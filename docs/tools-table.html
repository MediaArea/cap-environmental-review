Institutions must use separate tools to verify CAP data integrity before and after transfer.rsync uses checksums internally for both its delta-transfer algorithm and its automatic post-transfer whole-file verification, but does not output or persist these checksums as a fixity record. The --checksum (-c) flag changes rsync's file comparison method from size-and-time to a 128-bit checksum, but this is for internal transfer decisions and is not reported to the user. File-level fixity must be computed separately (e.g. with bagit, md5sum, sha256sum, etc) before and after transfer to create a persistent tamper-evidence record.No binding mechanism. rsync does not create or verify any binding between metadata and content. Embedded C2PA hard binding is preserved structurally (since the file is transferred byte-for-byte), but rsync cannot report whether the binding is intact.
